# SPK.ctf-2026 — безопасный импорт 50 заданий в CTFd

## Назначение

Импортёр читает `SPK_ctf_package.md`, извлекает 50 карточек, динамические параметры Initial/Decay/Minimum, названия, описания и точные флаги. Подсказки **не создаёт, не изменяет и не удаляет**. Новые задания создаются скрытыми (`hidden`), старые остаются в своём состоянии.

Повторный запуск сопоставляет задания по названию и категории. Поддерживается старое название без префикса ID и новое `SPK-WEB-01. ...`. Если уже есть решённые задачи, их обновление по умолчанию блокируется. **Автоматической смены типа существующего задания с `standard` на `dynamic` нет**: для таких задач требуется отдельное решение организатора с учётом истории решённых задач.

## Перед запуском

1. Сохранить резервную копию CTFd: Admin → Config → Backup → Export и отдельный бэкап базы данных.
2. Убедиться, что в `~/spk-ctf` лежат актуальные артефакты и исполняемые файлы для всех 50 заданий.
3. Сохранить API-токен администратора CTFd на VPS. Не передавать его в чат, Git или ZIP.
4. Настроить доступ к CTFd API: по локальному `http://127.0.0.1:8000` (если работает), либо через HTTPS с доверенным корневым сертификатом. Никогда не используйте `--insecure` без необходимости.

```bash
python3 -m pip install requests
cd ~/spk-ctf
mkdir -p importer
# Скопируйте import_challenges.py и SPK_ctf_package.md в ~/spk-ctf/importer/
read -rsp 'CTFd admin token: ' CTFD_TOKEN; echo
export CTFD_TOKEN
```

## Сначала dry-run (ничего не изменяет)

```bash
cd ~/spk-ctf/importer
python3 import_challenges.py --root ~/spk-ctf --url http://127.0.0.1:8000 --host 192.168.0.46 --upload-files
```

Скрипт создаст `import_plan.json`: перечень CREATE / UPDATE / BLOCKED и файлов. Проверьте особенно задачи без найденных файлов. Подсказки не входят в план.

## Выполнение импорта

После бэкапа и проверки dry-run:

```bash
python3 import_challenges.py --root ~/spk-ctf --url http://127.0.0.1:8000 --host 192.168.0.46 --upload-files --apply
```

Нужно вручную ввести `IMPORT 50`. Новые задания скрыты, чтобы участники не увидели недонастроенные карточки. Если уже решённые задания мешают импорту, не включайте `--allow-update-solved` без понимания последствий изменения баллов.

## Важные ограничения

- Не выполняйте импорт, если соревновательный раунд уже начался, без отдельного решения организатора.
- Файлы определяются только по строгому белому списку. Не публикуются `src.c`, `gen.py`, `solve.py`, `verify.py`, `flag.txt`, документация организатора.
- Отсутствующие вложения не генерируются. Подготовьте/проверьте их на VPS заранее.
- Уже загруженные файлы с тем же именем не перезаписываются и не удаляются. При обновлении артефакта проверьте и замените его вручную, чтобы не оставить устаревшую версию.
- Существующие конфликтующие флаги не меняются автоматически, а помечаются `FLAG REVIEW`.
- Если задачи с названием/категорией совпадают неоднозначно, скрипт прекращает работу.
- Для CTFd с нестандартным API или несколькими страницами по числу заданий выше стандартного проверьте ответ API и отчёт.
- Публичные порты Web/Crypto передаются в `connection_info` как HTTP, поскольку эти отдельные лабораторные сервисы не переведены на HTTPS.
- Если Web-03 и прочие задания требуют получателя обратного соединения, проверьте их из компьютера участника в изолированной сети.
- Импортёр не управляет подсказками даже при обновлении существующих заданий.

## После импорта

В админке CTFd проверьте динамический тип и параметры баллов, каждый флаг, скачивание файлов, работу сетевых сервисов и видимость. Опубликуйте скрытые задания перед стартом. Проверьте, что не осталось конфликтующих дубликатов под другим названием.
